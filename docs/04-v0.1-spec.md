## 2. Core concepts (domain model)

| Concept | Description |
|---|---|
| **Area** | A life context: Office, Client, Study, Personal, Reading (defaults; user-editable). Has a name, color, icon. |
| **Task** | A unit of work. Belongs to an Area. Has a type, optional time, duration, priority, energy, notes, subtasks. |
| **Task type** | `fixed` (exact start time) · `flexible` (duration + window, e.g. "1h between 9–11 PM") · `deadline` (due by date/time) · `habit` (recurring, counted) · `backlog` (no date) |
| **Template** | A reusable day plan (list of blocks with times). Assigned to days of the week. |
| **Block** | A scheduled time slot on a given day: generated from a template, a recurring task, or added manually. |
| **Occurrence** | One concrete instance of a recurring task/block on a specific date. Has its own status. |
| **Status** | `planned` → `active` → `done` / `skipped` / `missed` / `moved` |
| **Inbox** | Captured items with no area/time yet. |

### Task fields (v0.1)

| Field | Required | Notes |
|---|---|---|
| title | yes | |
| area | no (defaults to Inbox) | |
| type | yes (default `fixed` if time given, else `backlog`) | |
| start time / date | for `fixed` | |
| window (from–to) | for `flexible` | |
| due | for `deadline` | |
| duration | no (default 30 min) | |
| priority | no | `low` / `normal` / `high` |
| energy | no | `low` / `medium` / `high`: stored now, used by v0.2 engine |
| recurrence | no | RRULE (see §8) |
| notes, links | no | Markdown text |
| subtasks | no | Checklist |

## 3. Screens

### 3.1 Today view (main window)
- Vertical timeline of today, blocks color-coded by Area.
- Current-time line; current block highlighted.
- Side list: **Unscheduled today** (flexible tasks, deadlines due today), **Inbox count**, **Missed (n)**.
- Day navigation: ← yesterday · today · tomorrow →.
- Inline actions on a block: Done · Start · Snooze · Move · Skip · Edit.

### 3.2 Now view
- Large: current task, area, time remaining, subtasks checklist.
- Below: **Next up** (1 item) with start time.
- If nothing is scheduled now: show "Free time until HH:MM" + top 3 flexible/backlog tasks (simple sort by priority, then due). *(The smart engine comes in v0.2.)*

### 3.3 Templates
- List of templates; each shows its days of the week.
- Edit a template as a timeline of blocks (drag to resize/move).
- One template per weekday at most; holidays/overrides possible per date.

### 3.4 Inbox
- Captured items; quick triage: assign area, time, type, or delete.

### 3.5 Settings
- Areas (name, color), default reminder lead time, quiet hours, morning/evening review times,
  hotkey, theme, autostart toggle, data folder location.

### 3.6 Onboarding (first run only)
1. "What does a typical workday look like?": pick from a starter template
   (e.g. *Office 9–5 · Personal 6–8 PM · Client 9–10 PM · Study 10–11 PM · Read 11–11:30 PM*) and adjust.
2. Same for weekend (or skip).
3. Choose areas & colors (pre-filled).
4. Set quiet hours and review times.
5. Done → Today view, already filled. **Target: under 2 minutes.**

## 4. Quick add (global hotkey)

- Default hotkey: `Ctrl+Alt+Space` (configurable). Works when the app window is closed.
- Small floating input box; `Enter` saves, `Esc` cancels.
- Natural-language parsing (v0.1 subset):

| Input | Result |
|---|---|
| `client call 9pm` | fixed, today 21:00, default duration |
| `client call 9pm 45m` | fixed, 21:00, 45 min |
| `study dsa 1h tonight` | flexible, 1h, window = evening |
| `submit invoice by fri` | deadline, Friday 23:59 |
| `read every day 30m` | habit, daily, 30 min |
| `#client fix bug tomorrow 10am` | area = Client, fixed, tomorrow 10:00 |
| `buy cable` | inbox / backlog |

- Live preview under the input shows the parsed result before saving.
- Anything not understood stays in the title; the item goes to Inbox.

## 5. Notifications

### 5.1 Types

| Type | When | Actions |
|---|---|---|
| **Upcoming** | lead time before start (default 5 min) | Start · Snooze · Skip |
| **Starting now** | at start | Start · Snooze · Skip |
| **Ending** | at end of block | Done · +10 min · Not done |
| **Missed** | block ended with no action (see escalation) | Do now · Tomorrow · Backlog · Drop |
| **Deadline** | 24h and 1h before due | Open · Snooze |
| **Morning briefing** | first PC start of the day after configured time | Open |
| **Evening review** | configured time (default 22:30) | Review now · Later |

### 5.2 Escalation (N2)
1. At start → normal toast.
2. +10 min, no response → toast again (marked "still pending").
3. At block end, no response → status = `missed`, added to Missed list, tray badge count +1. **No further pop-ups** for that block.

### 5.3 Quiet hours & Focus Assist (N3)
- During quiet hours: no toasts; items queue and appear in the morning briefing / catch-up.
- If Windows Focus Assist / Do Not Disturb is on: rely on Windows to suppress; never bypass it.

### 5.4 Smart snooze (N4)
Options: **10 min** · **After current block** · **Tonight (start of evening)** · **Tomorrow (same time)**.

## 6. Adapt flows

### 6.1 Missed-task triage (A1)
- Missed items are listed in Today view and in the end-of-day review.
- Each offers: **Do now** (schedule into next free slot) · **Tomorrow** (same time) · **Backlog** · **Drop**.
- Tone: neutral. No red guilt counters; a calm neutral badge.
- Track `postponed_count` per task (used by A5 in v0.2).

### 6.2 Wake-up catch-up (A2)
- On app start, system resume from sleep/hibernate, or after a gap > 2 min in the scheduler clock:
  - Find every notification that **should have fired** during the gap.
  - Do **not** fire them all as toasts. Show **one** summary: "While you were away: 3 items" → opens a catch-up panel with triage actions.
  - Blocks still in progress are resumed normally.

## 7. Reflect flows

### 7.1 Morning briefing (R2)
- Triggered on first PC start/wake after the configured morning time (default 06:00).
- Shows: today's template, count of blocks, deadlines due, carried-over items.
- Actions: **Looks good** · **Adjust** (opens Today view) · **Use a different template** (e.g. Holiday).

### 7.2 End-of-day review (R1)
- Triggered at evening review time, or manually from the tray.
- Step 1: "Done X of Y" + list of completed items.
- Step 2: triage every unfinished/missed item (same actions as A1).
- Step 3: peek at tomorrow; optional quick add.
- **Target: under 60 seconds.**
- Saves a daily summary record (used by v0.3 weekly review).

## 8. Recurrence (P5)

- Stored as standard **iCalendar RRULE** strings (RFC 5545) for future calendar compatibility.
- v0.1 UI supports: daily · weekdays · weekends · specific days of week · every N days · monthly on date · monthly on Nth weekday · last day of month.
- Editing a recurring item asks: **This one** / **This and future** / **All**.
- Occurrences are generated on the fly for the visible range; only occurrences with state changes are stored.

## 9. System behavior

| Requirement | Detail |
|---|---|
| Autostart (Q1) | Registers to start with Windows (toggle in Settings, on by default). Starts minimized to tray. |
| Tray (D5) | Icon shows a badge for pending/missed. Menu: current task · Quick add · Open · Pause reminders 1h · Review day · Quit. |
| Closing the window | Hides to tray; does not quit. First time, show a one-time hint. |
| Single instance | A second launch focuses the existing window. |
| Storage (Q2) | Local SQLite database in the user's app-data folder. |
| Autosave & undo (Q3) | Every change is saved immediately. `Ctrl+Z` undoes the last action (at least last 20). Deleted items go to Trash for 30 days. |
| Crash safety | DB writes are transactional; a crash never corrupts data. |
| Time (Q4) | Store timestamps in UTC + the user's IANA time zone. Fixed tasks keep their *local wall-clock time* across DST changes. Re-schedule notifications on time-zone change and on resume. |
| Resources (Q5) | Idle: ~0% CPU (scheduler sleeps until the next event, no polling loop). Window closed: UI process unloaded; background process target < 20 MB RAM. |
| Theme / display (Q7) | Follows Windows light/dark by default; per-monitor DPI aware. |
| Keyboard (D6) | `Ctrl+K` command palette; every action reachable by keyboard. |

## 10. Edge cases checklist

- [ ] PC asleep during a reminder → appears in catch-up, not lost.
- [ ] PC off all day → next start shows catch-up + morning briefing (merged, not two pop-ups).
- [ ] Two blocks overlap → warning when creating; both still allowed.
- [ ] Block spans midnight (e.g. 23:30–00:30) → belongs to the start day.
- [ ] DST change → fixed tasks stay at the same local time.
- [ ] Time zone change (travel) → reminders recalculated, wall-clock times kept.
- [ ] User edits a template → affects future days only, never past ones.
- [ ] Recurring task edited "this one only" → exception stored, series unchanged.
- [ ] Quick add with unparseable text → saved to Inbox, nothing lost.
- [ ] App updated / restarted mid-block → block state restored.
- [ ] Many missed items (e.g. after vacation) → catch-up offers "Move all to backlog".
- [ ] Notification permission disabled in Windows → in-app banner explains how to enable.

## 11. Definition of Done

v0.1 is done when:

1. All features in §1 work as specified.
2. Every item in §10 is checked.
3. Onboarding takes **< 2 min**; end-of-day review **< 60 sec**.
4. Quick add from hotkey to saved: **< 3 sec**.
5. Measured idle CPU ≈ 0%; background RAM < 20 MB with the window closed.
6. Used daily by the author for **2 consecutive weeks** with no data loss and no silently missed reminder.
